# Real README set (`evals/real_readmes.jsonl`)

**What.** 80 intro sections from GitHub READMEs of permissively licensed repos: real product and launch copy
written in the wild, not generated by us. EVAL-ONLY: nothing here is ever training data (same rule as the rest of
`evals/`). Each row: `id` (rr-001..rr-080), `ai_draft` (the intro, plain text), `source: "github_readme"`, `repo`,
`url` (README html url), `licence` (SPDX from the GitHub API), `created_at`, `stars`, `fetched: 2026-11-02`,
`word_count`, `tells {stock_rate, em_dash_rate, emoji_rate}`.

**Rebuild.** `PYTHONUTF8=1 python hackathon/eval/collect_real.py` (deterministic: raw API responses are cached in
`hackathon/eval/_cache_real/`, which ignores itself; `--refresh` refetches, and live search results drift over time).
Tests: `python -m unittest hackathon/eval/test_collect_real.py`.

## How selected

1. **Search** (GitHub REST search API, sort by stars, 100 per query, 1 request/second). Each term below gets
   `created:>=2024-06-01 stars:>=20` appended:
   - `topic:saas`
   - `topic:productivity`
   - `topic:startup`
   - `topic:developer-tools`
   - `topic:ai-tools`
   - `"ai tool" in:description`
   - `"developer tool" in:description`
   - `"open source alternative" in:description`

   Union, sorted by stars then name, capped at 400 candidates.
2. **Licence** from the API's `license.spdx_id` (not the README text), allowed: MIT, Apache-2.0, BSD-2-Clause,
   BSD-3-Clause, ISC, CC-BY-4.0, CC0-1.0. Forks and archived repos dropped. 400 -> 274.
3. **Extract** the first prose section (text before the first `##`, or one of the next sections if that is an
   About/Overview/What-is section; Install/Usage/Features/etc. skipped). Badges, images, HTML, code blocks, tables,
   link URLs, nav rows ("Docs · Discord"), language pickers and GitHub alert markers are removed; link text is kept;
   soft-wrapped lines are joined; title and tagline lines keep their own line. Trimmed at a paragraph boundary to
   at most 220 words; kept only if 60-220 words, English (ASCII letters >= 95%, stopword share >= 12%), not
   list-only, not install-only. 274 -> 121 (too short 71, no prose 58,
   list-only 16, non-English 7, install-only 1).
4. **Enrich** with `pipeline/metrics.text_metrics` + `stock_hits` (no LLM). Kept only items with at least one tell:
   stock phrase, em dash, emoji, tricolon or "not X but Y" > 0. 121 -> 114.
5. **Dedup** by hash of the lowercased word sequence and by owner (one repo per org/user). 114 -> 110.
6. **Leakage**: drop any item sharing 8+ consecutive words with any non-system message in
   `hackathon/data/train.jsonl` or `valid.jsonl`. 0 dropped; the script asserts none remain in the output.
7. **Store** the first 80 by (stars desc, repo name) as rr-001..rr-080.

## Caveats

- **We cannot know whether a human or an AI wrote any of these READMEs.** "Has a tell" means a metric fired, not
  that the text is machine-written. The set is real-world copy that a user might paste in, not a labelled
  AI-vs-human corpus, and it has no human reference rewrite.
- Tricolons dominate the tell filter (72 of 80): product intros list features, so a list of three is often
  just a list. Only 32 have an em dash and 22 a stock phrase.
- Heavily skewed to AI and developer tooling, because that is what the 2024-2026 high-star search results are. It is
  not representative of marketing copy in general.
- Extraction is regex-based; a few items keep CTA lines ("Start a free trial →", "please star the repo") and
  short label lines. These are part of the real copy and were left in.
- Licence comes from GitHub's detection of the repo's LICENSE file. Redistribution needs attribution: keep `repo`
  and `url` with any excerpt.
