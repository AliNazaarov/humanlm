# FeatherLM

## What it does
FeatherLM is a copy editor for AI-drafted text: it rewrites AI-sounding marketing copy (landing pages, launch emails, LinkedIn posts) so it reads like a skilled human wrote it, without changing any fact. It runs an open model on Fireworks inside a verify-and-revise harness; the evaluation uses marketing copy, and the fine-tuning data is licence-clean general human prose (Common Pile).

Frontier models with a good prompt remove the AI tells, but they also drop or change facts and cut the copy short. A fact-safe rewrite is the part they don't give you.

## Results
**In one line:** our entry is `O3c_glm_prompt_harness_style`: an open model on Fireworks (GLM-5.3 Flash) inside a verify-and-revise harness. On the fact-safe gates it beats Claude Opus 5.5 with a strong prompt by a wide, significant margin at a small fraction of the cost, and it matches Claude inside the same harness. The independent judge is more mixed: it rates facts about even (it catches invented qualitative details our gates miss) and prefers Claude's prose, and our blind human A/B test (readers mostly recruited through a public page) leaned to Claude as well, not significantly. Every result is below, unedited; rows other than O3c are ablations.

**Headline metric: fact-safe human rewrite rate.** This is the share of rewrites that pass all four gates, defined once in [hackathon/harness/gates.py](hackathon/harness/gates.py):

| Gate | Passes when |
|---|---|
| G1 nothing invented | no new number, name, quote or attribution |
| G2 nothing lost | every number kept, at least 90% of names kept |
| G3 no AI tells | stock phrases, em dashes, "not X but Y", emoji and exclamations stay within the human band's upper bound |
| G4 not gutted | output is 0.7 to 1.3 times the draft's length |

## Who it's for and why fact-safety matters
- **Users:** founders, marketers and agencies who draft copy with AI, and the growing number of AI agents that write and post copy for companies.
- **Pain:** AI drafts read as machine-written, and asking a frontier model to "make it human" quietly drops or changes claims. Published marketing claims carry legal risk (truth-in-advertising rules), so a rewrite that changes a fact is worse than no rewrite.
- **Product:** an API that rewrites copy to read human and checks every number, name and quote against the draft before returning it, at open-model prices. Cost per 1k rewrites for every system is in the Results table above.
- **Tradeoff:** the verifier keeps facts but makes the model edit conservatively; an LLM judge still prefers Claude's prose on some marketing drafts (see Results and Limitations).

## Sponsor track: Fireworks
- **Inference:** every open-model row (GLM-5.3 Flash) runs on Fireworks serverless inference, including the verify-and-revise harness.
- **Fine-tuning:** SFT (LoRA) runs on the Fireworks Serverless Training API (ids and status in `hackathon/train/TRAIN_LOG.md`) and an AI-feedback DPO (GLM-5.3 labels, 66 pairs, 3 overridden by Ali). A fine-tuned model appears in the table only once its rows are evaluated.
- **Evaluation:** the pairwise judge (Kimi K3) runs on Fireworks.

## Reproduce the eval
```bash
make test   # metric, stats, runner and judge tests (offline)
make eval   # rebuilds results.json and RESULTS.md from the committed run files (offline, seconds)
```
Re-running a system calls its API: `hackathon/eval/run_frontier.py` for the frontier models, `hackathon/harness/harness.py` for the open models and the harness, and `hackathon/eval/judge.py` for the pairwise judge. Each run writes `evals/runs/hack_<system>.jsonl` plus a manifest `hackathon/runs/<system>.json` recording the model id, prompt hash, decoding, git commit and time.

## Method
- **Task and items.** The eval has 247 items (3 held-out items are excluded because their licence could not be established; `hackathon/report/heldout_excluded.json`). 130 come from `evals/eval_all.jsonl`: 100 dev and 30 trick items, each an AI-sounding draft written for an invented product brief. The other 117 are from `evals/heldout_pairs.jsonl` (120 minus the 3 excluded): real human passages and their AI-polished drafts, held out from training by a hash of the pair id. Every system rewrites the same items.
- **Train/eval separation.** Nothing under `evals/` is used for training. Any training pair whose draft or human text shares 8 or more consecutive words with a dev, trick or frontier eval file is dropped. That removed 162 pairs, and the split script asserts 0 overlap remains in train and valid (see [hackathon/data/SPLIT.md](hackathon/data/SPLIT.md)).
- **Prompt and decoding.** Every system gets the draft as the user turn and the shared system prompt (`SYSTEM` in `pipeline/infer.py`), plus the per-system prompt file its manifest names (the frontier "strong" instruction, `prompt_v2`, the humanizer prompt, the calm prompt). Decoding is whatever each run's manifest in `hackathon/runs/` records, and every row records what was actually sent: Claude Opus 5.5 accepts no sampling parameters, so it runs at the provider's default sampling with adaptive thinking at effort low and max_tokens 1500; GPT-6.1 and GLM-5.3 run with reasoning effort low; harness rows add up to 3 revise loops (best-of-3 rows draw three candidates).
- **Scoring.** `hackathon/eval/score_all.py` applies the four gates, plus the secondary tell metrics from `pipeline/metrics.py` (13 tell metrics, the share inside the human 10th–90th percentile band, and length ratio).
- **Statistics.** Rates get exact Clopper-Pearson 95% intervals. Means get percentile-bootstrap intervals (10,000 resamples, seed 0). A difference against the frontier reference is a paired bootstrap on the shared items, called significant at p < 0.05.
- **Pairwise judge.** An open model on Fireworks judges each pair, never a model from the frontier arm's family. It sees both orders, and a win counts only when both orders agree. It returns separate verdicts for facts and for style, and we report the flip rate and position-1 rate to show order bias.

## Limitations
- **The eval drafts come from one model family.** The dev and trick drafts were written by one model family about invented startups, so the style metrics reward undoing that family's tells. The held-out pairs are real human text, but their drafts are also machine-made: an open model "AI-polished" the human original (reverse distillation).
- **The metrics are screens, not human preference.** The gates and tell metrics are rules, and passing them does not prove a reader prefers the text. The pairwise judge and the small blind human test are the only preference signals.
- **The harness revises against the same gates we score.** Its high fact-safe rate is partly by construction. That is why we also report an independent judge (Kimi K3, a different model family from every system under test) and a blind human test. The judge prefers Claude Opus 5.5's prose on the synthetic marketing drafts, ties it on the held-out human text, and finds the fact edge in our favour.
- **Copying the draft is a control row.** `X0_copy_draft` scores the unchanged AI draft. It passes almost nothing on the dev split, so the gates can't be passed without rewriting there. On the held-out pairs it passes over half, because those AI-polished drafts carry few of the tells G3 checks, so that split mostly tests fact safety, not style.
- **Many comparisons.** We report every system in the table on several splits and every judge pair without a family-wise correction. The headline gate differences are p < 0.001 and survive one; judge results near p = 0.02 should be read as suggestive.
- **Latency is not measured the same way for every row.** Harness rows include every revise loop and any retry wait; the frontier runner times only the successful call.
- **No Gemini row.** Gemini 4 Argon was not tested (no paid quota on the day); a free-tier Gemini Flash-Lite run was attempted and stalled on rate limits, so it is not in the table.
- **Held-out near-duplicates of the training data.** The split keeps held-out and training pairs apart by id and exact text, not by overlap. 22 of the 120 held-out items share an 8-word run with the SFT training data, mostly template text, licence footers and reused news sentences (`hackathon/report/heldout_train_overlap.json`, provenance audit in `hackathon/report/HELDOUT_PROVENANCE.md`). Prompted and harness rows are unaffected; for fine-tuned rows, read the "Held-out, excluding ids that overlap the SFT train data" table.
- **Licence detail for one source.** 73 held-out items come from Common Pile's CC-licensed web subset, where each document carries its own CC licence; our pipeline stored "see source" rather than the per-document licence, so those items need their licence recovered from Common Pile metadata before redistribution.
- **Strict vs lenient fact checks.** The strict gates treat any changed number or capitalised word as a fact change, so harmless edits ("5" to "five", "Kenyan" to "Kenya") fail. The table shows both: strict, and lenient (those artefacts forgiven, `hackathon/audit/audit.py`). The harness leads Claude Opus 5.5 under both.
- **Independent audit.** `hackathon/audit/AUDIT.md` (re-run with `python hackathon/audit/audit.py`) reports what the gates don't: near-copies of the draft (more common for the harness than for Claude), tells the gates don't check (where Claude stays closer to the human range), and dropped draft sentences (much rarer for the harness than for Claude).
- **Our gates miss invented qualitative claims.** G1 checks new numbers, names and quotes only, so a rewrite can add a soft claim and still pass: O3j on dev-006 invents "Your dog hates the carrier. Your cat vanishes at the sight of it." and passes all four gates. The Kimi judge's facts column catches this (it favours Claude on facts for the best-of-3 rows O3j and O3d), which is why we quote that column next to the gate rate and added an open-model claim checker (O3k).
- **Ablations were tuned on the same eval items.** About a dozen harness variants (O3 to O3k) were developed against these items and the best-judged one was chosen afterwards, so the eval numbers for those rows are optimistic. Our entry is O3c, fixed before the later variants; the 80-item real README split was never used for tuning and is the out-of-sample check. O3h (humanizer prompt + harness) was started and stopped and has no row.
- **Claude refusals.** Claude Opus 5.5 refused held-out items ho-013 (a gene-synthesis part description) and ho-054 (a codeine-extraction passage) in every attempt (first run plus two resumes per arm); they are counted as Claude failures, as any system's missing item is.
- **Experiments not kept.** A workflow pairwise-selector experiment (30 items) was not kept: style got worse on the Kimi judge. It is listed in `hackathon/report/excluded_runs.json`, not on the leaderboard.
- **No system passes as human.** In the spot-the-human test (real held-out originals vs each rewrite, both orders, two judges), the judges picked the real human text over every system's rewrite almost every time, Claude's included; O3c is confused for human slightly more often than Claude only when order disagreements count. Read "human" in our headline as "no AI tells by our gates", not "indistinguishable from a person".
- **The LLM judges don't agree with human readers on style.** On the blind A/B items, both judges' style verdicts mostly disagree with the readers' per-item majority (counts in the Results block). Treat the judge style columns as weak evidence; the human A/B is the ground truth for "reads human", and it leans to Claude.
- **The judge is an LLM.** It has its own biases, including length and position. We run both orders and report the flip rate, but we have not calibrated it against human labels.
- **The fact checks are strict but crude.** Numbers and capitalised names are matched as strings, so a correct paraphrase of a name can count as a loss, and a fact that changes without any number or name changing is missed.
- **The frontier APIs can't match every decoding setting.** The open-model runs also use repetition_penalty 1.05, which the frontier APIs don't offer, and a model that rejects top_p runs at temperature only. Both are recorded per row.
- **The sample is small.** With 130 + 117 items, intervals are wide, so read every number with its interval.
