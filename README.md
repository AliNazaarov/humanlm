# HumanLM

## What it does
HumanLM rewrites AI-sounding marketing copy (landing pages, launch emails, LinkedIn posts) so it reads like a skilled human wrote it, without changing any fact. It is an open model, fine-tuned and served on Fireworks.

Frontier models with a good prompt remove the AI tells, but they also drop or change facts and cut the copy short. A fact-safe rewrite is the part they don't give you.

## Results
_The table is generated by `make eval` into [hackathon/report/RESULTS.md](hackathon/report/RESULTS.md). It is copied here at the freeze, never typed by hand._

**Headline metric: fact-safe human rewrite rate.** This is the share of rewrites that pass all four gates, defined once in [hackathon/harness/gates.py](hackathon/harness/gates.py):

| Gate | Passes when |
|---|---|
| G1 nothing invented | no new number, name, quote or attribution |
| G2 nothing lost | every number kept, at least 90% of names kept |
| G3 no AI tells | stock phrases, em dashes, "not X but Y", emoji and exclamations stay within the human band's upper bound |
| G4 not gutted | output is 0.7 to 1.3 times the draft's length |

## Reproduce the eval
```bash
make test   # metric, stats, runner and judge tests (offline)
make eval   # rebuilds results.json and RESULTS.md from the committed run files (offline, seconds)
```
Re-running a system calls its API: `hackathon/eval/run_frontier.py` for the frontier models, `hackathon/harness/harness.py` for the open models and the harness, and `hackathon/eval/judge.py` for the pairwise judge. Each run writes `evals/runs/hack_<system>.jsonl` plus a manifest `hackathon/runs/<system>.json` recording the model id, prompt hash, decoding, git commit and time.

## Method
- **Task and items.** The eval has 250 items. 130 come from `evals/eval_all.jsonl`: 100 dev and 30 trick items, each an AI-sounding draft written for an invented product brief. The other 120 are `evals/heldout_pairs.jsonl`: real human passages and their AI-polished drafts, held out from training by a hash of the pair id. Every system rewrites the same items.
- **Train/eval separation.** Nothing under `evals/` is used for training. Any training pair whose draft or human text shares 8 or more consecutive words with an eval draft is dropped. That check removed 155 pairs, and 0 overlaps remain (see [hackathon/data/SPLIT.md](hackathon/data/SPLIT.md)).
- **Prompt and decoding.** Every system gets the same system prompt (`SYSTEM` in `pipeline/infer.py`) with the draft as the user turn, at temperature 0.7, top_p 0.9 and at most 400 tokens. The frontier "strong" arm adds the rewrite instruction in `hackathon/eval/FRONTIER_STRONG.md`, and its label says so. Each run file records the decoding settings actually sent.
- **Scoring.** `hackathon/eval/score_all.py` applies the four gates, plus the secondary tell metrics from `pipeline/metrics.py` (13 tell metrics, the share inside the human 10th–90th percentile band, and length ratio).
- **Statistics.** Rates get exact Clopper-Pearson 95% intervals. Means get percentile-bootstrap intervals (10,000 resamples, seed 0). A difference against the frontier reference is a paired bootstrap on the shared items, called significant at p < 0.05.
- **Pairwise judge.** An open model on Fireworks judges each pair, never a model from the frontier arm's family. It sees both orders, and a win counts only when both orders agree. It returns separate verdicts for facts and for style, and we report the flip rate and position-1 rate to show order bias.

## Limitations
- **The eval drafts come from one model family.** The dev and trick drafts were written by one model family about invented startups, so the style metrics reward undoing that family's tells. The held-out pairs are real human text, but their drafts are also machine-made: an open model "AI-polished" the human original (reverse distillation).
- **The metrics are screens, not human preference.** The gates and tell metrics are rules, and passing them does not prove a reader prefers the text. The pairwise judge and the small blind human test are the only preference signals.
- **The judge is an LLM.** It has its own biases, including length and position. We run both orders and report the flip rate, but we have not calibrated it against human labels.
- **The fact checks are strict but crude.** Numbers and capitalised names are matched as strings, so a correct paraphrase of a name can count as a loss, and a fact that changes without any number or name changing is missed.
- **The frontier APIs can't match every decoding setting.** The open-model runs also use repetition_penalty 1.05, which the frontier APIs don't offer, and a model that rejects top_p runs at temperature only. Both are recorded per row.
- **The sample is small.** With 130 + 120 items, intervals are wide, so read every number with its interval.

## Pre-existing work vs built today
- **Pre-existing (2026-10-31 to 11-01):** the corpus pipeline, about 7.8k reverse-distillation pairs, `data/build_mix.py`, `pipeline/metrics.py` and its 29 tests, the 130-item eval set, and the Claude persona baseline file (`evals/baseline_frontier.jsonl`). No trained model was brought in; every model in the results was trained or run today.
- **Built today (2026-11-02):** everything under `hackathon/`. That covers the held-out split and the SFT data, the Fireworks fine-tune and serving, the harness and gates, the frontier runner, the pairwise judge, the statistics, the leaderboard and chart, the demo, the video, and this README.
